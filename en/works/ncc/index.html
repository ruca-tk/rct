01

Context

New Context Conference has been running since 2005. Over 20 events across Tokyo and San Francisco, each with its own standalone site — no central home, no browsable history, no way to search speakers across years. Event data going back to the first edition existed only in scattered old server files and Wayback Machine snapshots. I designed and built the NCC archive from scratch to solve that: a permanent, bilingual home for the entire conference history, with infrastructure built to serve every future event without needing a rebuild.

02

Direction

Each NCC event has its own strong visual identity — a distinct colour palette, imagery, and theme. The archive site needed to house all of them without competing with any of them. The solution was restraint: clean white, neutral typography, minimal colour. The site's job is to present the events clearly, not to have a personality of its own.

The archive page becomes a visual timeline by design — each event card uses its own key visual as the thumbnail, so 20 years of NCC identity appears as a grid. The site steps back and lets the history speak.

03

Key Decisions

Six decisions shaped both the editorial system and the infrastructure underneath it.

01. Dynamic Homepage The homepage serves two states. When an event is upcoming, it shows a countdown timer and a link to the event site — the archive becomes a launch pad. When no event is active, it shows the most recent event with a link to the archive. Both states are controlled entirely from the WordPress dashboard. The homepage is always current without touching the codebase.

02. Recovering 20 Years of History Event data going back to 2005 didn't exist in any organised form. I scraped speaker names, agenda details, themes, and photos from old server files and the Wayback Machine, then structured and migrated everything into the CMS. Every event from the first NCC through to the present is now searchable and browsable in a consistent format.

03. Speakers as a Custom Post Type Speakers are their own post type, independent of any single event. A speaker who has appeared at multiple NCC events has one profile linking to every edition they've participated in. From the dashboard it's now possible to search the full speaker history across 20 years of the conference — something that wasn't possible before.

04. Agenda as Repeatable Rows The agenda builder uses ACF repeatable row fields — time, session title, description, speakers. Anyone can build a complete event agenda from the dashboard without touching code. Adding a session is adding a row.

05. Gallery as Drag and Drop Event photos are added via a drag-and-drop upload area in the dashboard. Drop the images in, save, done. No file management, no custom markup required.

06. Custom Blocks for Event Pages Each archived event page — agenda, gallery, speakers — is built using custom ACF blocks. The structure is consistent across all events but the content is unique to each. New event pages can be created and populated entirely from the dashboard.

04

Design

The visual system is deliberately plain — white backgrounds, a single neutral typeface, restrained spacing. The archive page uses each event's key visual as the card thumbnail, turning the page into a timeline of NCC's 20-year visual history. The design steps back entirely and lets the content carry it.

The homepage manages two very different states — live event energy with countdown and CTA, and quiet archival presence when no event is active — within the same layout, so the transition between states feels natural rather than jarring.

05

Build

Custom WordPress theme with ACF, built on the same foundation as DG Incubation — custom post types, structured field groups, Polylang for bilingual JP/EN. The speaker post type has its own taxonomy linking profiles to events across years. The agenda and gallery are built with custom ACF blocks, making event pages reusable and editor-friendly. The data migration was a combination of manual entry and semi-automated parsing of Wayback Machine snapshots and old server files.

06

Outcome

Twenty years of NCC history now lives in one place, searchable and browsable in both Japanese and English. The editorial team can create and publish a complete event archive page — agenda, speakers, gallery — without any design or development involvement. The homepage automatically reflects whether an event is coming or has passed. The infrastructure will serve every future NCC event without requiring a rebuild.

07

Reflection

The data recovery process was the most time-consuming part of the project and I underestimated it significantly. Wayback Machine snapshots are inconsistent — some events had almost nothing recoverable, others were nearly complete. A proper audit of what actually exists before committing to scope would have made the process smoother. For future archival projects I'd treat the discovery phase as its own deliverable before any build work begins.
